# Validation Architecture & Data Integrity (`Docs/Validations/`)

## 1. Multi-Tier Validation Strategy

The Inventory Management System employs a **defense-in-depth validation strategy** across 5 distinct architectural tiers to guarantee data integrity, business invariant enforcement, and zero corruption of inventory ledgers:

```mermaid
graph TD
    Tier1[Tier 1: Client-Side Interactive Validation<br/>HTML5 + jQuery Validate + Unobtrusive] --> Tier2[Tier 2: Model Binder & Data Annotations<br/>[Required], [Range], [StringLength], [Unique]]
    Tier2 --> Tier3[Tier 3: Controller State Inspection<br/>ModelState.IsValid + [ValidateAntiForgeryToken]]
    Tier3 --> Tier4[Tier 4: Service Layer Business Invariants<br/>Zero Negative Stock, Duplicate SKU checks, Delete Guards]
    Tier4 --> Tier5[Tier 5: Relational Database Constraints<br/>Unique Indexes, Foreign Keys, DeleteBehavior.Restrict]
```

## 2. Validation Tiers Breakdown

### Tier 1: Client-Side Interactive Validation
- **Engine:** `jquery.validate.js` + `jquery.validate.unobtrusive.js` driven by unobtrusive HTML5 `data-val-*` attributes generated by ASP.NET Core Tag Helpers (`asp-for`, `asp-validation-for`).
- **Real-Time POS Stock Guarding:** On the dynamic Point-of-Sale checkout screen (`Views/Sales/Create.cshtml`), client JavaScript validates requested quantity against live on-hand `StockQuantity` before form submission, providing immediate visual warnings without roundtrip latency.
- **Dynamic Table Row Re-indexing:** In both Purchases and Sales dynamic builders, line item row deletions trigger instant re-indexing (`Items[0]`, `Items[1]`) so unobtrusive validation continues functioning smoothly on dynamic fields.

### Tier 2: Model Binding & Data Annotations
- Executed automatically during the ASP.NET Core request pipeline before controller action execution.
- Common attributes utilized:
  - `[Required(ErrorMessage = "...")]`: Ensures mandatory presence of vital business keys.
  - `[StringLength(100, MinimumLength = 2)]`: Prevents buffer overruns and empty strings.
  - `[Range(0.01, 100000)]`: Enforces realistic financial bounds on unit prices and contract rates.
  - `[Range(0, 10000)]`: Prevents negative stock levels and enforces operational thresholds.
  - `[EmailAddress]`, `[Phone]`: Validates communication format strings.
  - `[RegularExpression]`: Enforces username alphanumeric security rules (`^[a-zA-Z0-9_-]+$`).

### Tier 3: Custom Validation Attributes (`Validations/`)
- **`UniqueAttribute` (`Validations/UniqueAttribute.cs`):**
  A custom server-side validation attribute derived from `ValidationAttribute`.
  - **Purpose:** Verifies that a merchandise SKU is globally unique across the catalog before persistence.
  - **Implementation:**
    ```csharp
    namespace InventoryManagementSystem.Models
    {
        public class UniqueAttribute : ValidationAttribute
        {
            protected override ValidationResult? IsValid(object? value, ValidationContext validationContext)
            {
                if (value == null) return ValidationResult.Success;

                ApplicationDbContext context = new ApplicationDbContext();
                string sku = value.ToString();
                Product productFromDatabase = context.Products.FirstOrDefault(p => p.SKU == sku);

                if (productFromDatabase == null)
                {
                    return ValidationResult.Success;
                }

                return new ValidationResult("SKU must be unique");
            }
        }
    }
    ```
  - **Service-Layer Complement:** Complemented in `ProductService.IsSkuUniqueAsync` to support edits where `p.ProductID != currentProductId` (excluding self).

### Tier 4: Service Layer Business Invariants
- Validations that depend on multi-entity aggregate states and temporal business rules:
  1. **Stock Non-Negativity:** When processing sales in `SalesController` / `CreateSaleAsync`, available stock is checked immediately before debiting:
     ```csharp
     if (product.StockQuantity < item.Quantity)
     {
         return OperationResult.Fail($"Insufficient stock for {product.ProductName}. Requested: {item.Quantity}, Available: {product.StockQuantity}");
     }
     ```
  2. **Referential Integrity Delete Guards:** Evaluated before rendering confirmation views (`CheckCanDeleteProductAsync`, `CheckCanDeleteCategoryAsync`, `CheckCanDeleteSupplierAsync`).
  3. **Self-Governance Guards:** Prevents an administrator from deactivating, deleting, or stripping the `SuperAdmin` role from their own active session account.

### Tier 5: Relational Database Constraints (EF Core Fluent API)
- Ultimate deterministic safety layer enforced by Microsoft SQL Server:
  - **Unique Clustered/Non-Clustered Indexes:** `IX_Products_SKU` (`IsUnique()`) and `IX_SupplierProducts_SupplierID_ProductID` (`IsUnique()`).
  - **Decimal Precision Enforcements:** `decimal(18,2)` on all monetary columns (`UnitPrice`, `ContractPrice`, `TotalAmount`, `UnitCost`).
  - **Foreign Key Referentials & Delete Restrictions:** `DeleteBehavior.Restrict` on historical transaction relationships (`Products -> SaleItems`, `Products -> PurchaseItems`, `Suppliers -> Purchases`, `Categories -> Products`).

## 3. Validation Summary Catalog

| Entity / Target | Property | Validation Mechanism | Constraint / Boundary | Enforcement Tier |
| :--- | :--- | :--- | :--- | :--- |
| `Product` | `SKU` | DataAnnotation & Unique Index | Unique, 3–50 chars, alphanumeric | Tier 2, 3 & 5 |
| `Product` | `UnitPrice` | `[Range(0.01, 100000)]` | Positive currency value, `decimal(18,2)` | Tier 2 & 5 |
| `Product` | `StockQuantity` | `[Range(0, 10000)]` | Invariant $\ge 0$, cannot decrement below 0 | Tier 2 & 4 |
| `Product` | `LowStockThreshold`| `[Range(0, 1000)]` | Invariant $\ge 0$ | Tier 2 |
| `Category` | `CategoryName` | `[Required]`, `[StringLength(100, Min=2)]` | 2–100 non-empty characters | Tier 2 |
| `Category` | `Products` | `DeleteBehavior.Restrict` | Deletion blocked if active child products exist | Tier 4 & 5 |
| `Supplier` | `Phone` & `Email`| `[Phone]`, `[EmailAddress]` | RFC email compliance, standard phone format | Tier 2 |
| `SupplierProduct` | `(SupplierID, ProductID)` | Composite Unique Index | Only 1 contract per vendor-product pair | Tier 5 |
| `SupplierProduct` | `ContractPrice` | `[Range(0.01, 100000)]` | Positive currency rate, `decimal(18,2)` | Tier 2 & 5 |
| `SupplierProduct` | `LeadTimeDays` | `[Range(1, 365)]` | Operational duration between 1 and 365 days | Tier 2 |
| `PurchaseItem` | `Quantity` & `UnitCost` | `[Range(1, 10000)]`, `[Range(0.01, 100000)]` | Must order $\ge 1$ item with positive cost | Tier 2 & 4 |
| `SaleItem` | `Quantity` | `[Range(1, 10000)]` | Must order $\ge 1$ item $\le$ on-hand stock | Tier 1, 2 & 4 |
| `ApplicationUser` | `Username` | Regex + Unique Identity | Unique, 3–50 alphanumeric characters | Tier 2 & 5 |
| `ApplicationUser` | `MasterRecoveryKeyHash` | Cryptographic PBKDF2 | Salted hash of 128-bit key | Tier 4 & 5 |
